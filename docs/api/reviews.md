# Reviews API

Отзывы проходят модерацию: новый отзыв создаётся со статусом `pending`
(«на модерации»), публикуется после одобрения администратором
(`published`) или отклоняется (`rejected`). Публичные списки и рейтинг
пользователя учитывают только `published`. Модерация (approve/reject,
фильтр по статусу) — в `docs/api/admin.md`.

### Статусы отзыва

| Статус | Описание |
|--------|----------|
| `pending` | На модерации: виден только автору (`GET /reviews/my`), в рейтинг не входит |
| `published` | Опубликован: в публичном списке, учитывается в рейтинге |
| `rejected` | Отклонён: скрыт из публичного списка, в рейтинг не входит |

### Длина текста

- Запись (`POST /reviews`): `text` — trim, 1–150 символов
  (`REVIEW_TEXT_MAX_LENGTH` из `@edem/contracts`).
- Чтение (ответы API): `text` — до 1000 символов: read-схема намеренно
  терпимая к существующим отзывам (лимит 150 enforced только на запись).

## POST /api/v1/reviews

Создание отзыва (авторизация обязательна, mutation rate limit).
Отзыв создаётся со статусом `pending`: публично не виден, рейтинг цели
не меняется, пока админ не одобрит (см. `docs/api/admin.md`).

Тело:

```json
{ "tripId": "uuid", "targetUserId": "uuid", "rating": 5, "text": "Отличная поездка!" }
```

`rating` — целое 1–5; `text` — trim, 1–150 символов.

Ответ `201` — отзыв (элемент как в `GET /reviews/my`, со
`status: "pending"`).

| Код | HTTP | Описание |
|-----|------|----------|
| `VALIDATION_FAILED` | 400 | Невалидное тело (пустой/пробельный `text`, `text` > 150, `rating` вне 1–5) |
| `SELF_REVIEW` | 400 | Отзыв самому себе |
| `TRIP_NOT_ACTIVE` | 400 | Поездка отменена |
| `TRIP_IN_PAST` | 400 | Поездка ещё не началась/не завершена |
| `NOT_PARTICIPANT` | 403 | Автор не участник поездки |
| `FORBIDDEN` | 403 | Неверное направление (только пассажир ↔ водитель) |
| `NOT_FOUND` | 404 | Поездка или пользователь не найдены |
| `ALREADY_REVIEWED` | 409 | Отзыв по этой поездке уже оставлен (в любом статусе) |

## GET /api/v1/reviews/my

Отзывы, оставленные текущим пользователем (авторизация обязательна).
Все отзывы автора — **в любом статусе**; каждый элемент включает `status`
(`pending`/`published`/`rejected`) и опциональный `tripId`. Новые первыми,
без пагинации (bare array). Элемент — как в публичном списке.

## GET /api/v1/reviews/user/:userId

Публичный список отзывов о пользователе с cursor-based пагинацией.
Возвращает **только опубликованные** (`status: "published"`) — pending и
rejected скрыты. Требует только валидного `userId` — авторизация не
обязательна.

### Параметры

| Параметр | Тип | Обязательный | Описание |
|----------|-----|--------------|----------|
| `userId` | UUID | ✅ (path) | ID пользователя |
| `limit` | number | ❌ | Количество отзывов на страницу, 1-50, default 20 |
| `cursor` | UUID | ❌ | ID последнего элемента предыдущей страницы |

### Ответ

```json
{
  "items": [
    {
      "id": "uuid",
      "author": {
        "id": "uuid",
        "name": "Иван",
        "avatar": "https://...",
        "rating": 4.8
      },
      "targetRole": "driver",
      "rating": 5,
      "text": "Отличная поездка!",
      "status": "published",
      "date": "11 августа 2026 г.",
      "tripRoute": "Moscow → SPb"
    }
  ],
  "pagination": {
    "nextCursor": "uuid-of-last-item",
    "hasMore": true,
    "limit": 20
  }
}
```

`nextCursor` — ID последнего элемента текущей страницы; передавайте его как
`cursor` в следующем запросе. `null` означает, что это последняя страница.

### Примеры

**Первая страница:**
```bash
curl /api/v1/reviews/user/{userId}?limit=10
```

**Следующая страница:**
```bash
curl /api/v1/reviews/user/{userId}?limit=10&cursor={nextCursor}
```

### Ошибки

| Код | HTTP | Описание |
|-----|------|----------|
| `NOT_FOUND` | 404 | Пользователь не найден |
| `VALIDATION_FAILED` | 400 | Невалидный формат `cursor` (не UUID) |

Примечание: `cursor` валидного формата, за которым больше нет данных
(включая отсутствующие или удалённые записи), возвращает **пустую страницу с `200`**
(`items: []`, `hasMore: false`, `nextCursor: null`) — это не ошибка.
